# Genesis ARC V2.1 — Lossless knowledge compression and capacity sweep

## 1. Research question

Can exact skill maps be retained more efficiently under a fixed storage budget, without changing the V1.9 inference algorithm or V2.0 admission/eviction policy? V2.1 compares raw tables, bounded-DSL program codes, and lossless delta codes. It does **not** claim compression improves the learner's underlying inference capability.

## 2. Implementation

- Preserves the V1.7 grammar and V1.9 Bayesian learner as exact source dependencies.
- Keeps V1.9 `utility_gate` inference and utility-based admission/eviction constant across all arms. The candidate re-observation path matches the V1.9 update policy; it does not refresh `last` merely because the same candidate is re-admitted.
- `raw`: 8 outputs × 3 bits = 24 bits per mapping.
- `program`: if a mapping belongs to the shared 12-primitive DSL, encode a 2-bit length field plus 4 bits per primitive token; otherwise store the raw 24-bit mapping. Program length is 1–3 in the current grammar (the 2-bit length field leaves one code unused). The shared primitive dictionary/interpreter cost is excluded from every arm.
- `delta`: a minimum spanning forest with exact program/table roots and lossless sparse patches. Each patch uses `ceil(log2(n))` parent-pointer bits, 4 bits for the changed-cell count, and 6 bits per changed cell (3-bit index + 3-bit output value). The forest can contain multiple roots where independent program/table roots are cheaper.
- Every entry receives the same assumed 16-bit metadata allowance. Thus raw entry cost is 40 bits. This is a transparent bit-accounting model, **not** a measured Python heap footprint, actual hardware SRAM measurement, or fully packed binary file format.
- Simulation inference reads decoded maps. The codec changes retention capacity, not CPU compute cost. All three codecs are lossless; `run.selftest()` round-trips all 642 DSL mappings and fuzzes mixed DSL/out-of-DSL delta sets up to 64 maps. Unit tests cover exact round trips, bit accounting and budget enforcement.

## 3. Experimental design

- Two within-noise groups: 10% and 20% observation noise; 8 independent seeds per group.
- Each seed runs 6 environments in each of four phases: acquire A, shift to B, return to A, and novel out-of-DSL. Total: 24 source environments per seed, 192 per noise group, 384 across both groups.
- A/B environments each contain two operations drawn from the bounded DSL and two out-of-DSL mappings; the novel phase uses out-of-DSL mappings.
- Eight methods: raw 6/12/24/48-entry memories (240/480/960/1920-bit budgets), program-coded 480/960-bit memories, and delta-coded 480/960-bit memories.
- Same source worlds, test tasks, and observation-noise uniforms are paired across methods within each seed. Each source environment receives 32 active queries; accuracy is checkpointed at 0/8/16/32 queries.
- Frozen recall probe: the final A environment is replayed after acquisition and again after the B shift, with a fresh working posterior and 16 queries. Probe results are not written back to long-term memory.
- CSV contains 6,272 checkpoint rows per noise group (including frozen probes). The two noise groups use distinct seed offsets; comparisons are made within noise group, not as a causal comparison of noise levels.

## 4. Main results

Depth-4 composition accuracy at the 16-query checkpoint (A-return values are phase means over six environments per seed; frozen A-after-B is one probe per seed):

| Memory | Budget | 10% noise: first A return | 20% noise: first A return | 10% noise: frozen A after B | 20% noise: frozen A after B |
|---|---:|---:|---:|---:|---:|
| Raw 6 | 240 bit | 57.55% | 40.61% | 27.83% | 25.98% |
| Raw 12 | 480 bit | 68.55% | 49.46% | 46.97% | 29.79% |
| Program | 480 bit | 68.59% | 53.26% | 49.02% | 43.55% |
| Delta | 480 bit | 69.22% | 54.22% | 51.56% | 47.75% |
| Raw 24 | 960 bit | 86.17% | 73.84% | 91.80% | 76.46% |
| Program | 960 bit | 91.28% | 77.67% | 93.46% | 78.32% |
| Delta | 960 bit | 91.06% | 77.54% | 93.46% | 78.32% |
| Raw 48 | 1920 bit | 90.28% | 77.52% | 95.02% | 78.32% |

Across the six A-return environments, compression stores more skills than raw-12 on average at the 16-query checkpoint: program/delta retain 13.15/13.40 skills versus 12. By the final novel episode, both retain 12.00 (10% noise) and 12.25 (20% noise), versus 12 raw entries. At 960 bits, program/delta retain 25.33/25.44 skills at the first return (10%) and 26.19/26.65 (20%), versus 24 for raw-24. By the final novel episode, program/delta retain 24.00/24.25 (10%) and 25.12/25.38 (20%) versus 24 raw entries.

Paired seed-level bootstrap (8 seeds, 10,000 resamples) shows:
- 20% noise, 480-bit program vs raw-12 on frozen A-after-B recall: +13.77 percentage points; 95% bootstrap interval +2.54 to +26.27 pp.
- 20% noise, 480-bit delta vs raw-12: +17.97 pp; interval +7.81 to +28.91 pp.
- 10% noise, corresponding frozen-recall differences are small and intervals include zero.
- 480-bit program/delta A-return phase differences vs raw-12 are negligible at 10% noise; at 20%, gains are +3.79/+4.75 pp with intervals +0.62 to +7.70 and +1.48 to +7.99 pp.
- Delta is not reliably better than program coding: paired delta-vs-program intervals include zero at both budgets and noise settings.

## 5. Interpretation

1. Lossless coding improves storage efficiency. At the first A return, the 480-bit codecs retain about 9–12% more skills than raw-12; the 960-bit codecs retain about 5–11% more than raw-24.
2. The performance benefit is conditional. At 20% noise, 480-bit compression improves frozen A recall after a B shift; at 10% noise, the effect is not clear. At 960 bits, compressed methods are close to or somewhat above raw-24, but delta is not demonstrably superior to program coding.
3. Doubling raw memory from 12 to 24 entries produces a much larger A-return phase gain than compression alone: +17.61 pp at 10% noise and +24.38 pp at 20% noise (16-query depth-4 accuracy). Capacity remains a stronger lever in this benchmark.
4. Compression gains diminish as the memory fills with out-of-DSL maps. Such maps require raw roots or relatively expensive patches; the shared DSL prior is most useful for in-grammar skills.
5. On the fully novel out-of-DSL phase, all methods remain close (about 20–23% depth-4 accuracy at 16 queries). Compression does not solve open-world generalization.

## 6. Limitations

- Only 8 seeds per noise condition; bootstrap intervals are descriptive and should not be treated as definitive evidence.
- The 16-bit metadata allowance and shared primitive dictionary are modeling assumptions. No actual packed binary representation, physical memory, energy or latency was measured.
- The learner receives a known noise rate and operates in a resettable, four-operation, eight-state synthetic world. This is not a real digital-life ecosystem or general intelligence benchmark.
- Delta coding is an exact minimum-spanning-forest cost model. It does not yet include the implementation complexity of robust versioning, corruption recovery, or random-access decoding in a production store.
- The raw-48 arm is not fully saturated in every checkpoint; treat it as a high-capacity reference, not a matched-used-bits comparator.
