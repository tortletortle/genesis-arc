# Genesis ARC V2.0 — Long-term skill consolidation pilot

## Scope
Based on the exact V1.9 source in main commit 4bf82dcd5dc8013163182a556fc644724704ab56. This pilot remains a synthetic 4-operation, 8-state, resettable environment, not a population simulation. The earlier V1.9 record shows only 0.25 exact saved maps out of 4 at first return in the 10% noise group (0 at 20%). This suggests a retention problem but does not establish its cause.

## Method
Protect up to half of a 12-map bank if a previously stored skill predicts observations from a later episode: require four distinct observed inputs for at least one operation and log marginal evidence ratio against the independent uniform latent mapping model >= log(10). Rank eligible skills by positive episode count, cumulative capped evidence, and confidence. Remaining slots use FIFO with confidence tie-break. No true map, test labels or probe results enter memory update. Credit is an observational evidence proxy, not causal downstream utility. Metadata costs are not byte-matched. Negative evidence does not reduce accumulated credit. Unprotected ablation is identical except no protected slots. Utility_2x is V1.9 utility_gate with 24 maps. All dual-memory arms reuse utility_gate inference.

## Design
Two independent groups of 4 seeds, offsets 20000 and 30000, noises .10 and .20 respectively; 4 rounds per A/B/A/novel phase (64 source environments per group), 5 methods, 32 source queries each. Frozen probes reuse the last A world and a fixed independent task/noise tape, once immediately after A, once after B; fresh working posterior each time, 16 queries but no memory writeback. Same source environments and paired observation tapes across methods. 2800 checkpoint rows across groups, not independent observations. The planned 8 seeds x 6 rounds per group run exceeded the tool time limit; completed pilot deliberately uses 4 x 4. No statistical significance claim; noise is confounded with seed group.

## Observations: depth-4 accuracy after 16 queries (%)
| Method | First return .10 | First return .20 | Frozen A before B .10 | Frozen A after B .10 | Frozen A before B .20 | Frozen A after B .20 |
|---|---:|---:|---:|---:|---:|---:|
| fifo_exact | 61.91 | 42.77 | 51.76 | 49.80 | 54.49 | 55.08 |
| utility_gate | 54.10 | 29.10 | 90.43 | 43.16 | 92.19 | 53.12 |
| utility_2x | 98.05 | 76.56 | 90.43 | 83.98 | 92.19 | 84.18 |
| consolidated | 63.09 | 32.03 | 90.43 | 54.30 | 92.19 | 45.51 |
| unprotected | 36.13 | 34.57 | 90.43 | 26.37 | 92.19 | 36.91 |

Consolidation versus unprotected improves frozen recall after shift by 27.93 pp (.10) and 8.59 pp (.20), but is worse than utility_gate in the latter group. Per-seed improvements in frozen recall over unprotected: .3203125, -.0625, .1015625, .7578125 and -.046875, .1875, .1640625, .0390625. Increasing capacity from 12 to 24 strongly improves immediate return and fixed recall in both groups; results favor testing memory capacity and compression before adding more mechanisms. This does not prove capacity is the sole cause or that the method generalizes to longer streams.

## Reproduction
Python/NumPy; run from this folder:
```
python -c 'import continual; continual.selftest()'
python continual.py --seeds 4 --rounds 4 --out main
python continual.py --seeds 4 --rounds 4 --noise .2 --offset 30000 --out robust
```
Use raw CSV from the delivery zip; for the table filter budget==16 and phase==return, episode==0, or probe_acquire/probe_shift and group by method. Self-tests (baseline, evidence sign, reuse credit, capacity, zero-evidence) passed. Further work: preregister capacity sweep with longer A/B gaps, byte-matched storage, confidence calibration and frozen-probe evaluation; validate on >=16 seeds per group before selecting architecture.
