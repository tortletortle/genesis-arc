# Genesis ARC V2.2 — 自组织知识字典研究报告

## 1. 研究问题

V2.1 研究如何在固定存储预算下压缩已经掌握的技能映射。V2.2 进一步研究：**能否不依赖预先给定的固定原语列表，而是从已观测技能中自主挑选可复用映射，构建一个共享知识字典，并用它精确表示新的复合技能？**

本研究只检验有限状态函数映射的结构复用和描述长度，不将其解释为通用概念形成或一般智能。V2.2 是独立研究分支，尚未与 Genesis ARC V1.5.1 遗传种群/生态环境主线集成；V1.5.1 的完整种群演化能力不在本轮实验的证明范围内。

## 2. 方法

### 2.1 合成环境

- 状态数：8；每个技能是一个确定性映射 \`f: {0,...,7} -> {0,...,7}\`。
- 每个数据集生成4个隐藏随机置换作为潜在基础操作。
- 训练集包含4个基础操作锚点和24个由基础操作长度为2或3的序列组合而成的复合映射。
- 另有8个复合映射作为留出集；不参与字典拟合。
- 两种到达顺序：基础操作锚点先到（anchor-first）和全部训练映射随机打乱（shuffled）。
- 噪声条件：每次输入输出观测的对称错误率为5%和20%。每个输入重复观测5次，按众数估计输出。报告分别记录估计映射与真实映射的一致率，以及压缩编码对估计映射的无损还原率。

### 2.2 自组织字典算法

1. 候选项仅来自当前训练前缀中已经观测到的映射；隐藏原语标签和留出映射不进入优化器。
2. 对字典候选执行二元素前瞻。原因是对本任务的独立随机置换，单独加入一个基础操作往往不能表示任何其他技能，而两个操作的组合就能表示复合技能。
3. 选择使整个训练集总描述长度下降最多的候选对；之后逐个加入带来正边际收益的候选。
4. 最多保留8个字典项，程序最大深度3；候选字典项必须是已经观察到的技能映射。
5. 对无法由字典精确组合得到的映射，直接存储原始表；不做近似或静默纠错。
6. 对每个数据前缀重新拟合，用于比较到达顺序影响。这是批量重拟合，不是在线增量算法。

### 2.3 存储成本模型

| 项目 | 计费 |
|---|---:|
| 每个技能元数据 | 16 bit |
| 原始映射表 | 8个输出 × 3 bit = 24 bit |
| 每个动态字典项的索引/版本描述 | 8 bit |
| 程序长度字段 | 2 bit |
| 每个程序 token | \`ceil(log2(K))\` bit，最少1 bit |

其中 K 是字典项数量。字典项本身来自已存储的技能映射，因此其24 bit原始表已经计入技能存储；额外只收取8 bit字典描述成本。

固定 DSL 对照使用 V1.7 的12个固定原语。分别报告：
- **免费先验口径**：假设固定 DSL 已由系统预装，不计字典构建成本。
- **全额计费口径**：每个固定原语收取24 bit映射表和8 bit描述，共384 bit。

这是一种透明的抽象描述长度模型，不等同于实际文件大小、内存占用、能耗或运行延迟。

### 2.4 对照与消融

- Raw：所有技能均以原始映射表保存。
- Fixed DSL：使用 V1.7 的固定12原语字典。
- Random dictionary：从训练映射中随机选择与自组织字典同等数量的候选，重复12次取均值。
- No pair look-ahead：关闭二元素前瞻，只允许单项贪心加入。
- Oracle dictionary：直接提供真实隐藏基础操作，仅作为不可部署的上界，不参与自组织算法。

### 2.5 未知原语留出

另设一组更严格的测试：4个隐藏原语中只将3个作为独立锚点呈现；训练复合映射和留出复合映射仍可能使用第4个未显露原语。算法只能从可见技能中选字典项。该测试用于区分“复用已见结构”与“恢复从未独立出现的潜在原语”。

## 3. 实验规模

- 每种噪声16个独立随机种子，共32个主实验数据集。
- 每个主数据集：4个锚点、24个训练复合映射、8个留出复合映射。
- 两种到达顺序各自记录7个前缀检查点，共448条前缀记录。
- 未知原语测试：每个种子、每种噪声各一组，共32组。
- 5次/输入的重复观测；同一数据集内所有方法使用相同估计映射。

## 4. 主要结果

### 4.1 训练集压缩

| 指标 | 5%噪声 | 20%噪声 |
|---|---:|---:|
| 真实映射估计准确率 | 99.11% | 89.06% |
| 自组织字典平均项数 | 4.00 | 4.00 |
| 字典项精确率 | 100.00% | 92.19% |
| 字典项召回率 | 100.00% | 92.19% |
| 训练映射可程序编码比例 | 84.82% | 67.41% |
| 编码无损还原率（相对估计映射） | 100.00% | 100.00% |
| Raw 总成本 | 1120 bit | 1120 bit |
| 自组织字典总成本 | 748.13 bit | 831.13 bit |
| 相对 Raw 节省 | 33.20% | 25.79% |
| 固定 DSL（预装字典免费） | 1119.38 bit | 1120.00 bit |
| 固定 DSL（12项字典全额计费） | 1503.38 bit | 1504.00 bit |
| 随机字典（同项数，12次随机抽样均值） | 1145.76 bit | 1148.50 bit |
| 无二元素前瞻消融 | 1120 bit，未形成字典 | 1120 bit，未形成字典 |
| Oracle 字典成本 | 748.13 bit | 790.88 bit |

按种子配对 bootstrap（16 seeds，10,000次重采样），自组织字典相对 Raw 的节省为：
- 5%噪声：平均371.88 bit，95%区间 [368.00, 375.00]。
- 20%噪声：平均288.88 bit，95%区间 [253.13, 322.13]。

相对随机字典的节省为：
- 5%噪声：397.64 bit，95%区间 [393.46, 401.52]。
- 20%噪声：317.38 bit，95%区间 [280.91, 350.67]。

固定 DSL 在免费先验口径下对这些随机隐藏映射几乎没有压缩收益，成本约为Raw；全额计入12项固定原语字典后成本约1503–1504 bit。随机选择同等数量字典项的平均成本约1146–1149 bit，也没有优于Raw。自组织字典能从训练映射中挑出适配当前任务的基础操作。相对固定 DSL 免费先验口径，自组织字典的平均节省为371.25 bit（5%噪声，95%区间[367.63,374.38]）和288.88 bit（20%噪声，区间[253.37,322.25]）。

### 4.2 留出复合技能

| 指标 | 5%噪声 | 20%噪声 |
|---|---:|---:|
| 留出映射估计准确率 | 99.22% | 88.28% |
| 留出映射程序编码比例 | 99.22% | 70.31% |
| 留出编码无损还原率（相对估计映射） | 100.00% | 100.00% |
| 留出集成本 | 225.00 bit | 261.63 bit |
| 留出集Raw成本 | 320 bit | 320 bit |

注意：无损还原率是“解码结果等于已估计映射”的比例；真实映射估计错误时，无损解码并不意味着语义正确。20%噪声下，映射估计准确率下降，导致部分复合技能无法匹配已发现的程序，编码器将其安全回退为Raw表。

### 4.3 到达顺序影响

首次达到“字典精确率至少75%，且相对Raw节省至少5%”的平均训练前缀长度：

| 噪声 | 基础操作先到 | 随机打乱到达 |
|---|---:|---:|
| 5% | 8.00项 | 18.25项 |
| 20% | 9.00项 | 21.25项 |

最终完整训练集上，两种顺序均收敛到相同字典质量（5%噪声下精确率/召回率均为100%；20%噪声下均值约92.19%）。这说明字典重拟合能够修正早期顺序带来的暂时性选择，但随机顺序会显著推迟形成有效字典。

### 4.4 未显露基础操作

在只显露3/4个基础操作、但复合任务仍使用第4个隐藏操作的条件下：

| 指标 | 5%噪声 | 20%噪声 |
|---|---:|---:|
| 字典平均项数 | 5.13 | 4.94 |
| 对4个真实隐藏原语的召回率 | 51.56% | 45.31% |
| 对可见3个锚点的召回率 | 68.75% | 60.42% |
| 未显露第4原语被选中次数 | 0 | 0 |
| 留出复合映射程序编码比例 | 22.92% | 14.58% |
| 留出编码无损还原率（相对估计映射） | 100.00% | 100.00% |

当前算法不能从复合映射中保证恢复从未独立出现的潜在原语；未显露的第4个原语从未被直接选中字典项（均值为0）。它会选择部分可见锚点和复合映射作为替代字典项，并对其余映射回退到Raw存储。这个结果是当前方法的边界，不应包装成“自动发现了隐藏原语”。

## 5. 解释

1. 在已出现基础操作锚点的合成环境中，数据驱动的字典选择能够识别出可复用映射，并在严格计入动态字典描述成本后，把训练集存储成本降低约26%–33%。
2. 二元素前瞻是本实验设置下的必要机制。只做单项贪心时，两个原语联合才产生的组合收益无法被发现，最终退化为Raw成本。
3. 锚点先到明显加快字典形成；随机顺序下，系统需要观察更多映射才能积累足够的组合证据。
4. 编码本身是精确的；噪声影响的是映射估计和程序匹配率。对不能匹配的映射使用Raw回退，避免了有损重建。
5. 当一个潜在原语从未作为独立技能出现时，当前候选生成机制不能保证恢复它。观察到的复合映射只能作为替代字典项。

## 6. 限制

- 隐藏基础操作是8状态随机置换；并非自然语言、物理动作或现实世界语义操作。
- 仅使用长度2–3的复合程序；更深层组合和大字典搜索未验证。
- 16 bit元数据、8 bit字典描述、token位宽是抽象成本模型；没有实现真正的紧凑二进制序列化，也没有测量RAM、延迟、能耗。
- 每个输入固定重复观测5次，使用多数投票；没有主动选取区分性输入，也没有处理非平稳噪声。
- 字典按每个数据前缀批量重拟合；尚未实现在线插入、淘汰、版本迁移、并发读写或崩溃恢复。
- 每种噪声16个种子。bootstrap区间描述本合成任务的种子波动，不代表跨任务或现实场景的泛化保证。

## 7. 下一步

V2.3 不应简单扩大字典，而应研究真正的在线自组织：
- 增量更新，不必每次从头拟合；
- 新项加入时的全局收益估计和淘汰策略；
- 旧程序引用字典版本的稳定性与原子迁移；
- 从复合技能提出中间操作候选，并用主动区分实验验证；
- 将抽象位成本落实为实际二进制格式，再测真实字节数、编码/解码时间和内存峰值。
